Yata Native Framework 14 — предварительный аудит и натурные испытания
05.11.2026. Рабочий проект: C:\Users\Yata\Desktop\Download\project

РЕЗУЛЬТАТ

Подготовлены C++ реализации корневых схем Language / Quick Settings / Date,
статическая ShellPanels.lib, независимый тестовый потребитель, измерительные
скрипты, записи нативных панелей и C++ вариантов, а также запись реального трея.
Исправлен прежний регресс мгновенного закрытия и зависимость материала от фокуса.
Это тестовая версия профиля Windows 11 26100, НЕ завершённое соответствие 1:1.
Матрица V01 пока не пройдена. Неполные сценарии не обозначены как успешные.

Runtime остаётся из двух файлов: YataNativeFramework.exe и
YataNativeFramework.Patch.dll. ShellPanels.lib статически включена в EXE.
Отдельный SDK: ShellPanels-v14-sdk-x64-Release.zip; бинарники стендов находятся
в artifacts и не являются дополнительными runtime-зависимостями приложения.
VPN-провайдеры, подключения и сетевые настройки в этой работе не менялись.
Плитки стенда работают с локальной моделью и возвращают намерения приложению.

КОД И АРХИТЕКТУРА

source/ShellPanels/ShellPanels.h — публичные Host, Model, Kind, TrayPart, Action.
source/ShellPanels/ShellPanels.cpp — C++ деревья контролов, привязки и команды.
Material.h — Composition HostBackdrop, цветовые эффекты, шум, solid fallback.
Calendar.h — календарная сетка из настоящих кнопок с круглыми днями.
ControlStyles.h — состояния native Button/Slider, шаблоны встроены в C++.
source/NativeTray/NativeFlyout.h — внутренняя HWND/XAML/Composition оболочка.
TrayApp интегрирован с Host; добавлены --lang / --quick / --date.

Прежнее DismissInactive, мгновенно скрывавшее HWND, удалено. Съезд заканчивается
по завершению Composition batch; generation защищает отменённые завершения.
Surface и материал остаются живы до окончания выхода. Own tray press и отпускание
обрабатываются отдельно. Эвристика LastInputInfo для повторного открытия удалена.
Материал применяется также к пользовательскому контенту и к меню ПКМ.

Quick Settings и каталог: вертикальный переход 250/167 мс.
Language: вертикальный профиль 83/83 мс.
Date: горизонтальный переход справа 250/167 мс. Его вход пока медленнее эталона;
ниже приведено измерение и отдельная задача коррекции, а не утверждение о паритете.

При сворачивании календаря область уведомлений теперь увеличивается вверх
до прежней верхней границы. Конечная геометрия исправлена; плавный переход
высоты, аналогичный Shell, ещё не реализован.

SetModel обновляет открытые плитки и ползунки без обратной генерации команд.
Материал пересоздаётся только при изменении темы/tint/luminosity либо системной
политики, а не при каждом движении ползунка. Исправлено возвращение к схеме
после SetContent: прежний custom tree больше не переиспользуется ошибочно.

Граница библиотеки улучшена, но ещё не идеальна: legacy Menu(mode,width)
связан с командами демонстрационного приложения внутри private transport.
Структурные коллекции и часть ручных кистей обновляются при повторном открытии.
Calendar использует native Buttons, но пока не предоставляет полный набор
Calendar/Table/Selection UIA patterns. Эти ограничения включены в план.

МЕТОДИКА

Windows 11 build 26100.9711 / 24H2, 2560x1600, DPI 144 (150%), монитор 240 Гц,
NVIDIA RTX 4070 Laptop GPU. Полный профиль — machine-profile.json.
Сравнение относится именно к этой сборке и её текущей конфигурации.

Фон стенда RGB(96,96,96). Область записи: x=1440, y=0, 1120x1600.
Нативные панели открываются физическими кликами. В независимом C++ стенде
открытие задаётся WM_APP; закрытие внешним кликом и проверки контролов используют
физический ввод. Отдельная tray-light.mp4 использует реальные клики по нашему
виджету; CLI только выбирает схему до начала очередного цикла.

Данные медиа, уведомлений, сети и яркости различаются: в C++ это fixtures.
Текст, обложки и значения нельзя включать в общий pixel diff как одинаковые
данные. Сравнивались фон, отдельные края, размеры, поведение и элементы,
для которых имеется сопоставимый эталон. Глобальный SSIM не выдавался за паритет.

Цвет измеряется по lossless PNG, полученным CopyFromScreen, в свободном от
текста участке Quick Settings (x=575, y=1270, 10x100 относительно записи).
Это локальная выборка, не равенство всех цветов на всех фонах.
VerticalSpans — пороговые интервалы материала вдоль выбранной колонки;
они не являются UIA bounding box. Для Date верхняя выборка начинается с y=80.

Видео: DDAGrab, запрошено 240 Гц, duplicate frames отключены, H.264 NVENC, VFR.
Медиана интервала — около 4.167 мс; p95 по записям — примерно 16.7..41.7 мс.
Есть более длинные интервалы, включая статические участки и снятие PNG.
Среднее число записанных кадров в секунду заметно ниже 240. Эти данные не
заменяют PresentMon/ETW и не доказывают 240 представленных кадров в секунду.

*-events.json и временная шкала видео имеют стартовое смещение FFmpeg.
Длительности motion-measurements.csv считаются от обнаруженного движения края,
а не просто от отметки входного события. Y отслеживается по x=1006, X для Date —
по строке y=900. Порог видимости и допуск 2 px от установившейся позиции дают
наблюдаемый отрезок движения, а не точное время внутренней анимации Shell.

В стенде исправлены две ошибки измерения: SetCursorPos заменён физическими
координатами; фоновое окно перестало перекрывать закрывающуюся C++ панель.
Для подготовки фон кратко поднимается, получает фокус и возвращается в обычную
Z-группу до сценария. Проверяются класс цели taskbar и нейтральный фон.
Shell_InputSwitchDismissOverlay разрешён как штатная поверхность закрытия Lang.
Один неверный тёмный фрагмент отбракован и перезаписан; он не участвует в итогах.

Точные строки и условия находятся в CSV; эти числа не являются сертификацией
совпадения easing, input latency или всех промежуточных кадров.

В tray-light.mp4 внешний клик по фону действительно вызывает съезд каталога
вниз. Во время наблюдаемого выхода образец материала остаётся около 234.3..234.4;
мгновенного переключения на белый fallback в этом сценарии не обнаружено.

Меню языка в эталоне отсутствует. Сняты ПКМ сети, звука, батареи и часов.
По указанию пользователя pointer-relative Y системного меню батареи НЕ копируется.
Все наши tray-widget меню, включая legacy меню самого виджета, используют
единый отступ от рабочей области над панелью задач. Это утверждённое отличие.

ПРОВЕРКИ

Release и Debug: по 202 строки PASS, включая CLI/протокол, 3125 размещений,
native controls, фокус, отмену анимации, UIA и независимый Host.
100 подтверждённых Open->Closed циклов в каждой конфигурации:
  Release private bytes 66027520 -> 65830912; GDI 7 -> 7.
  Debug   private bytes 66363392 -> 66162688; GDI 7 -> 7.
В каждой серии 238 уведомлений видимости. В двухсекундных замерах idle CPU
зафиксировано 0.000% одного ядра. Это короткая выборка, не проверка энергопотребления
и не доказательство отсутствия всех утечек, в частности GPU memory.

Проверены UIA RangeValue, отражение live Model в слайдере, отсутствие feedback
команды, один callback на физический клик fixture-плитки, Escape у четырёх меню.
Эти проверки повторены у потребителя, собранного только с экспортированным
публичным заголовком и ShellPanels.lib. Клиентские проверки production EXE прошли.
Зависимости зафиксированы dumpbin в dependencies.txt: дополнительная поставка
WinUI/WebView/CRT DLL не требуется, системные компоненты Windows остаются нужны.

После общего тестового прогона legacy меню виджета получило ту же нормализацию Y,
что профильные меню. Release/Debug пересобраны; этот путь проверен в живой записи
tray-light.mp4. Хэши стенда сохранены в манифестах записей; хэш production EXE —
в deployment.json. Тесты не приравниваются к доказательству визуального 1:1.

ПЕРЕПОДКЛЮЧЕНИЕ

При замене EXE воспроизведён A06: applied=0, error=0x80070490, callbackErrors=1
на уже работающем Explorer. Это НЕ проблема VPN и НЕ исправленный дефект.
Подключение восстановлено одним перезапуском Explorer; открытые папки сохранены
и восстановлены. В текущем состоянии applied=2, error=0, attach=0, 88x48 DIP.
Исторический callbackErrors=1 сохраняется в счётчиках, новых ошибок в idle нет.
В короткой idle-выборке patch по-прежнему получает события (refresh +7, chrome +5),
хотя pollingTimers=0. Оптимизацию лишних обновлений нельзя считать завершённой.

Используется прежняя проверенная patch DLL из активного пути, SHA256
E79814D9C387E31EC5335990BF2380651B1251A0E7E23E0AEF054F5A6D766961.
Формат shared memory остаётся v13. Исходная сборка создаёт совместимую DLL;
отличие её файла по хэшу не является изменением протокола. Смена DLL не была
способом исправления отображения; новая библиотека находится в EXE.
layout.ini сохранился побайтово; light/light/transparency восстановлены в 1/1/1.

ЧТО ОСТАЛОСЬ ДО ПРИЁМКИ 1:1

1. Скорость входа Date и точная траектория; анимация изменения высоты календаря.
2. Media artwork/метаданные/кнопки, paging Quick Settings, размеры и глифы отдельных
   контролов, полная структура уведомлений и вторичных страниц.
3. Неактивирующее поведение Language, полный клавиатурный контракт календаря,
   UIA Calendar/Selection/Table, tooltips и все pressed/disabled/focus состояния.
4. Полное live переключение темы для ручных кистей/шаблонов; high contrast,
   transparency off, battery saver, системное увеличение текста, локализация.
5. Реальные 100/125/200% DPI и переходы между мониторами; математический тест
   размещения их не заменяет. Пересчёт высоты Date при смене монитора.
6. Типизированные команды каждого пункта контекстных меню, динамические коллекции,
   удаление legacy зависимости демонстрационного меню из private transport.
7. A06 reconnect, холодное открытие/повторный parse шаблонов, стоимость chrome
   событий и интеграция анимации ширины трея. Ширина пока меняется без анимации.

Порядок: reconnect и вход Date -> theme/model/UIA -> оставшиеся схемы и состояния
-> все DPI/input/policy сценарии -> lossless masked pixel diff и ETW -> приёмка.
Подробные критерии и привязки к тестам находятся в FIX-PLAN.csv / TEST-PLAN.csv.
