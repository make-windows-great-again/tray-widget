РЕЗУЛЬТАТ
43 состояния прошли автоматические проверки фактического XamlRoot DPI,
ширины, размещения в рабочей области и наличия семи подписей дней недели.
Это функциональная приёмка масштабирования, НЕ полное попиксельное совпадение.
Светлая тема: 100, 125, 150, 175, 200, 225, 250% (30 состояний).
Тёмная тема: 100, 150, 250% (13 состояний).
Включены Date expanded/collapsed, Quick Settings, Language; на короткой
рабочей области — обе страницы Quick Settings. Нативные эталоны сняты на
том же мониторе. 225% native снимался отдельно для Date.

10 смен масштаба при открытом Date прошли без закрытия панели, накопления
смещения якоря и потери свёрнутого состояния. Видео: accepted-hot/transition.mp4.
Рабочая DPI-последовательность: 100 → 125 → 150 → 175 → 200 → 225 → 250 →
175 → 100 → 150. Начиная с 250% календарь свёрнут.

ПКМ C++: Clock и Volume на 100/150/250%. Нижний отступ физического окна
меню от рабочей области во всех шести случаях равен 12 DIP. Размеры окон:
100% Volume 246×102 px, Clock 191×68 px;
150% Volume 370×156 px, Clock 288×104 px;
250% Volume 616×258 px, Clock 479×172 px.
UIA корень popup может указывать на owner; для геометрии берётся Win32 rect.
Нативный комбинированный прогон ПКМ прерван при неактивном Clock HWND; он
не засчитан как полная парная приёмка. Сохранён валидный эталон Volume 100%.

ИЗМЕНЕНИЯ
- TextBlock использует Segoe UI Variable, как измеренный нативный Date.
- Header Date: 48 DIP вместо 50. Фокусная строка и границы остаются отдельными.
- Ручная календарная сетка заменена OS CalendarView. Стандартный контрол
  отвечает за локализацию, клавиатуру, выбор даты, виртуализацию и UIA.
  Day chrome округляется Windows Composition без подмены событий выбора.
- Today в тёмной теме использует тёмный текст поверх светлого accent.
- На короткой рабочей области Date показывает две недели. Порог 720 DIP
  выводится из измеренного профиля; точная точка переключения Windows между
  доступными масштабами не установлена и не объявляется публичным контрактом.
- Quick Settings при том же ограничении высоты показывает один ряд. Доступны
  прокрутка и две кнопки страниц для шести демонстрационных плиток. Нижние
  элементы больше не обрезаются на 250%. Данные и действия остаются fixture.
- Host подписывается на отправленные оконные DPI/display/work-area сообщения,
  XamlRoot.Changed и изменение размера текста. Пересчёт переносится в MSG pump.
  Якорь хранится в исходных физических координатах, поправка Language не
  накапливается. DPI для меню берётся у целевого монитора, а не старого HWND.
- DPI-стенды используют PMv2 для координат, настоящий Settings Scale и finally
  для возврата исходного масштаба. Библиотека системные настройки не меняет.

ОСТАВШИЕСЯ РАСХОЖДЕНИЯ
Высота тела Date в последовательном DPI-прогоне (native / C++, физ. px):
100% 355 / 355; 125% 443 / 443; 150% 534 / 536; 175% 623 / 622;
200% 710 / 713; 225% 420 / 420; 250% 469 / 470.
После смены DPI CalendarPanel сохраняет отдельный кеш размера ячейки. Это
создаёт отклонение до 3 px в данной последовательности. Эксперимент со сбросом
через ClearValue нарушил открытие на этом OS Island и в финальный код не вошёл.
Измерение невключённого в visual tree CalendarView также приводило к потере
подписей/смещению дат: Resize теперь ждёт IsLoaded. Регрессионные кадры не
включены в accepted-наборы; все accepted кадры проверяют семь подписей.

Окружность Today, внутренние отступы календаря, glyphs, hover/press, focus ring
пейджера, вторичные страницы и все детали material/shadow ещё не сертифицированы
как 1:1. Верхняя Date-карточка и Media используют тестовые данные; сравнение
полного изображения по SSIM поэтому не является корректным критерием.

Не проверены: два физических монитора с разным DPI, 300% (нет стандартного
пункта на этом дисплее), отдельный Accessibility Text size, high contrast в
новом CalendarView, auto-hide/перенос taskbar, весь набор локалей и touch input.
Подписка TextScaleFactorChanged — реализация обработки, а не отметка о приёмке.
A06/F05 (повторное подключение patch после замены EXE) остаётся открытым.
