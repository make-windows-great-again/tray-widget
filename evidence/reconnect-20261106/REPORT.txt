tray-widget — обработка исчезнувших XAML Diagnostics handles
06.11.2026, после v16. Windows 11 24H2 / 26100.9711.

ИСПРАВЛЕНИЕ
Watcher раньше вызывал Fail() при любой ошибке GetIInspectableFromHandle.
ERROR_NOT_FOUND (0x80070490) одного исчезнувшего элемента тем самым снимал
декорацию, очищал подписки и переводил весь backend в Faulted.
Теперь этот код удаляет только соответствующий кандидат и продолжает discovery.
Повторяющееся сообщение об исчезнувших handles записывается один раз за подписку.
Другие HRESULT не подавляются: сохраняются восстановление исходного UI и Fail().
Журнал ошибки дополнен этапом и HRESULT: refresh / visual-tree-resolve-handle /
visual-tree-watch-element / window-dispatch.

Документация Microsoft указывает, что GetIInspectableFromHandle может завершиться
ошибкой, когда Diagnostics больше не держит ссылку на элемент:
https://learn.microsoft.com/en-us/windows/win32/api/xamlom/nf-xamlom-ixamldiagnostics-getiinspectablefromhandle
Исправление ограничено ERROR_NOT_FOUND; прочие причины не считаются исчезновением.

РЕГРЕССИОННЫЙ ТЕСТ
Настоящий Watcher работает с управляемым IXamlDiagnostics и загруженным XAML Island.
До исправления: regression-before.log, FAIL на исчезнувшем handle рабочего owner.
После исправления: шесть новых проверок проходят в Release и Debug:
- исчезнувший чужой handle не отключает рабочую декорацию;
- удаление owner переводит контроллер в Connecting;
- исчезнувший handle при discovery не прерывает подписку;
- следующий валидный Add находит и оформляет настоящий XAML owner;
- callback старого поколения не обращается к кешу нового поколения;
- E_ACCESSDENIED сохраняет Faulted и освобождает ресурсы декоратора.
Подмена проверки tray-thread существует только при NATIVE_TRAY_SELFTEST.

НАТУРНАЯ ПРИЁМКА
tools/shell-parity/Test-ReconnectDpi.ps1 запускает владеющий процессами Test-Live
на настоящем Explorer с уже установленной DLL. Рабочий экземпляр перед тестом
должен быть закрыт. Меняется стандартный масштаб Settings с возвратом в finally.
dpi-final/results.json: 100 / 150 / 200 / 250%, по 36 PASS, всего 144.
На каждом масштабе: 20 detach/reconnect, принудительная ошибка декоратора,
намеренное завершение тестового EXE и подключение нового процесса к тому же broker.
Всего 80 detach/reconnect и четыре crash/restart; Explorer PID 32036 сохраняется.
Исходные 150% (144 DPI) восстановлены, layout.ini совпадает по SHA256.

ПОПРАВКИ СТЕНДА, НАЙДЕННЫЕ НА 250%
1. Подтверждение команды приходит до следующего XAML arrange. Зафиксировано:
   mode=2, revision=7, requested=88 DIP, actual=44 DIP. Стенд теперь дожидается
   фактической ширины с прежним ограничением времени, записывая промежуточные
   значения в live-layout-observations.csv. Начальный сбой: dpi/250.
2. После намеренного Kill() ожидание cleanup иногда принимало ожидаемый выход
   за неожиданное завершение приложения. Только это ожидание использует AllowExited;
   остальные по-прежнему прерываются при неожиданном выходе. Начальный сбой:
   dpi-accepted/250. Этот каталог — промежуточный, итоговый набор — dpi-final.
3. Finally ждёт завершения принадлежащего тесту EXE до восстановления layout.ini.
   Отдельный EvidenceDirectory предотвращает перезапись результатов прошлой приёмки.

УСТАНОВКА
Для диагностической и окончательной DLL выполнены два перезапуска Explorer;
пути и WINDOWPLACEMENT двух папок восстановлены. Перезапуски нужны для замены
загруженного модуля и не включаются в успешную серию reconnect.
При установке финальной DLL ранняя проверка через 4.5 s застала неготовую
регистрацию notify-icon. Приложение само повторило регистрацию и подключилось
без дополнительного перезапуска: fixed-install.json / fixed-install-ready.json.
Окончательные хеши, состояние приложения и окружение: deployment.json.
Локальный runtime в bin/Release обновлён; по-прежнему один EXE и один DLL.
Опубликованные архивы v16 не заменялись.

ГРАНИЦЫ ВЫВОДА
Изначальный production F05 не воспроизвёлся даже на диагностической DLL ДО
исправления (baseline-live.log, baseline-dpi-restart.json). Поэтому совпадение
HRESULT с историческим сбоем не доказывает общую причину. F05 остаётся OPEN;
новая диагностика позволит определить точный этап при следующем воспроизведении.
Исправленный сценарий исчезнувшего handle отмечен отдельно как F27.
Проверялись четыре масштаба одного физического монитора; это не приёмка mixed DPI.
Изменений визуальной разметки панелей в этом коммите нет; новая попиксельная
приёмка и запись анимаций для этого изменения не выполнялись.

ВОСПРОИЗВЕДЕНИЕ

Build.ps1 -Configuration Debug -SelfTest
После установки свежей DLL и закрытия рабочего EXE:

Файлы ранних попыток сохранены отдельно; итоговый DPI-набор: dpi-final.
