Галерея: длинные горизонтальные жесты, 06.11.2026

Требование: один жест может пересечь несколько вкладок, прокрутка заканчивается
на первой и последней. Приложение в трее не запускалось и не устанавливалось.
Работа выполнялась в отдельном GallerySwipeBench / XAML Island.

Причина и решение

Исходная галерея использовала OS Pivot. Его реализация показывает текущую
страницу и ближайших соседей при direct manipulation. Это согласуется с
описанным появлением пустых страниц при длинном жесте; физический тачпад
в этой сессии не использовался. Исходный NativeControls.h взят из c45a169;
его Git blob проверен: 9ff8d72b73b1c0050f340c4e8e135aeb32bb9dc5.

Системные заголовки Pivot сохранены. Содержимое шести вкладок находится в
конечной ленте ScrollViewer / StackPanel с Mandatory snap points. Каждая
страница заранее загружена, занимает ширину viewport и ограничена своей рамкой.
Пролистывание и инерция остаются системными; таймера анимации в PageStrip нет.
Цена этого решения — layout всех шести страниц вместо соседнего окна Pivot;
это намеренный выбор для небольшой фиксированной галереи.

Дополнительные найденные проблемы:
- слабые ссылки на неназванные XAML wrappers могли истекать при живом native
  дереве; элементы теперь разрешаются из корня и фактического Children;
- animated ChangeView оставлял остаток 0.433 DIP при 250%; конец выбора заголовка
  теперь выравнивается точно, запоздавшее завершение не отменяет новый запрос;
- запоздавший BringIntoView от текстового поля возвращал уже скрытую страницу;
  запросы неактивных страниц подавляются, активным сохраняется вертикальная
  координата, горизонтальный прямоугольник фиксируется по viewport;
- клавиатурный фокус переходит на видимую страницу, неактивная страница не
  получает его через запоздавшее восстановление. Tab учитывает границы страниц;
- DPI harness теперь ждёт появления вариантов Scale вместо фиксированных 180 мс.

Поведение Pivot проверялось по первичному исходнику Microsoft:
https://github.com/microsoft/microsoft-ui-xaml/blob/main/dxaml/phone/lib/Pivot_Partial.cpp
UpdateVisibleContent и настройка IsRequestBringIntoViewIgnored описывают обе
особенности. Это исходник WinUI, а исполняемый контрол здесь Windows.UI.Xaml;
он служит объяснением, а не утверждением о полном совпадении исходников ОС.
Перехват BringIntoView находится на не прокручивающемся StackPanel перед
горизонтальным ScrollViewer. Публичный контракт TargetElement/TargetRect и
OriginalSource описан Microsoft:
https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.uielement.bringintoviewrequested?view=winrt-26100

Приёмка

PASS: 8 прогонов — 100/150/200/250% в светлой и тёмной теме, по 925 проверок
реального XAML дерева в каждом. Дополнительно во всех прогонах прошли четыре
инъецированных жеста и клавиатурная проверка Ctrl+Tab/PageUp/PageDown с контролем
фактического фокуса. Исходный масштаб 150% восстановлен (FinalDpi=144).
Все accepted-* относятся к одной Release-сборке GallerySwipeBench, SHA256:
B965217FF187833928C35B922AF49137C9DA269BCBCA6CB213A767E1B497B481

Полная Release-сборка с -SelfTest прошла с первой попытки: 1147 PASS,
MSVC 14.51.36231, Windows SDK 10.0.26100.0; журнал release-tests.log.
В заключительной проверке ShellPanels за 100 циклов private bytes выросли
с 67674112 до 68022272, GDI handles остались 7→7. Это проверка существующего
host, а не измерение стоимости всех шести страниц галереи.

Записаны видео исходного Pivot и исправленного варианта в обеих темах при 150%.
В baseline CSV: 1 страница в покое, 3 при жесте, также 5 отсчётов с нулём
отображаемых страниц. В исходном варианте свайп за первый край переводит 0→4,
за последний — 5→1. Исправленный вариант сохраняет соответственно 0 и 5,
а все шесть страниц имеют рассчитанные размеры в течение жеста.
baseline-reference/ChecksPassed=false означает, что регрессионные assertions
нового pager к старой версии не применялись (ChecksRequested=false).

Воспроизведение:
  .\tools\shell-parity\Build-GallerySwipe.ps1
  .\tools\shell-parity\Test-GalleryDpi.ps1 -Record
  .\Build.ps1 -Configuration Release -SelfTest
Для DPI-прогона нужна открытая страница Display Settings и свободный рабочий
стол. Подготовка старого заголовка описана в tools/shell-parity/README.txt.

Общие проверки рассматривают реальные XAML bounds, а не копию расчёта pager:
шесть загруженных страниц, отсутствие промежутков, конечную ширину, оба
направления, дробные промежуточные положения, края, прерывание выбора, точность
конца перехода, сохранение текста, изменение размеров, UIA IsOffscreen,
фактический фокус и BringIntoView. Дополнительно проверяются внутренний и
внешний вертикальные ScrollViewer, удаление внешних C++ ссылок и unload/reload.

Файлы accepted-* — финальные прогоны; результаты, CSV, events.txt и PNG находятся
внутри каждого каталога. baseline-reference — исходный Pivot. regression-before
сохраняет первоначальное падение проверки выравнивания при 250%.
Прочие экспериментальные записи исключены из Git.

Ограничения

InjectTouchInput проверяет сенсорный путь Windows, а не физический Precision
Touchpad. На 100% контакт проходит три вкладки, на 150/200% — две, на 250% — одну:
длина контакта ограничена рабочим столом. Программный прогон проходит всю ленту
на каждом масштабе. Отдельная ручная приёмка реального тачпада остаётся нужна.

Узкое окно 500 физических пикселей намеренно оставляет место для контакта;
это стресс ширины pager, не эталон полной разметки приложения при каждом DPI.
Видео: запрос 120 кадров/с, DDAGrab VFR без дублирования; фактическая частота
презентации и работа на 240 Гц этим измерением не подтверждаются. CSV содержит
состояние UI/layout, а не timestamps отображения каждого кадра compositor.
FFmpeg сообщил коррекцию повторяющихся DTS; эти сообщения сохранены в recorder.log
(консольные CR развёрнуты в строки). Видео пригодны для визуального сравнения,
но не для точного измерения длительности анимации; средняя частота записи около
68 кадров/с, ниже запрошенных 120.
Первые жесты на видео отделены от последующих программных/клавиатурных проверок.

VPN, сетевые провайдеры, исходники patch DLL и публичный ABI ShellPanels не менялись.
Runtime остаётся из 1 EXE и 1 DLL; тестовые EXE находятся отдельно в artifacts.
Архивы релиза v16 не заменялись. Открытые пункты прежнего аудита F05/F26/F28
этим исправлением не закрываются.
